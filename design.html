Design gallery

Every state the launcher can currently render, at its real size. Free-form — nothing here is bound to GPUI. Edit the tokens in :root and all 34 cards follow; edit any card in place to try a layout. The rules are in design/DESIGN.md, the values in design/design-system.yaml, and node design/check.mjs fails when a card claims a size it does not render or drifts off the 16px gutter. The eventual rewrite in launcher.rs reads straight off the class names: .win is the root div, .bar the 52px search header, .row a 44pt result, .preview the 280pt pane.

Palette

The five semantic roles from theme.rs. A service palette maps onto these and nothing else; row tints are derived from --accent at 14 / 6 / 35 %.

Search & shell states

The six things the popup can be doing while it is a list. Window height is 84 + rows×44 clamped to 400, so the cards get shorter as results thin out.

Providers

One card per result source. Applications suppress their subtitle (the name is the whole row); everything else shows a subtitle, falling back to a capitalised provider name. Glyph icons live in a 24pt tile at 11px; real app icons are 24×24 images.

Preview pane

Cmd-Shift-P adds a 280pt pane to the right and grows the window to 760. The pane is border-left: 1px divider, 16px side padding, 12px text on 17px. At least five rows stay visible so the list never collapses under it.

Action menus · ⌘K

Same 44pt rows, no icons. Unselected actions go muted so the highlighted one carries the weight. Six visible at a time — the Files menu has seven and scrolls. Footer switches to ↵ Run · Esc Back.

Output screen

Shell execution replaces the list with a 24pt title row and a 240pt scrollable box on panel_fill. The window pins to 364. stderr is appended to stdout; a non-zero exit appends Process exited with ….

Confirmation prompt

The backend owns consent. When an action carries a prompt the launcher stages it instead of sending it: a tinted card under the search bar, mouse targets that route through the same Return/Escape handlers, and a footer that switches to Apply/Cancel. Row clicks go inert until it resolves.

Filmstrip

The wide browse is a strip, not a list: five frames on a perspective row, the focused one largest, centres at 0/255/421 from the middle. The band is inset 16 above and below, bleeds past both side edges, and only the focused frame carries an accent border. Wallpapers run 984×334 with 320/190/142 frames of 226/160/120, dimmed toward the surface as they recede (1.0 / 0.72 / 0.52). Themes run 760×284 with 248/146/110 frames of 176/124/92. A theme frame is the card itself — the theme's surface, its six accents, its name — so at distance the surface drops back to the panel and only the palette stays, and a light theme never outshines the one in focus. The dot marks the theme the desktop is wearing.

Palette variants

The same markup with four token overrides. This is the whole theming contract: a service palette maps to surface / label / muted / accent / outline_variant and nothing else changes. Rows re-tint themselves because the selection and panel washes are color-mix() of --accent.

34 states, zero JavaScript. Tokens live in :root; the derived row tints are declared on .win so a [data-theme] override re-tints the whole card. Geometry tokens (--row-h, --icon, --preview-w, --win-r) are the GPUI constants verbatim, so a change here has one obvious destination in launcher.rs.

Not modelled: live filtering, keyboard navigation, the Pill/QML frontend, and the web preview iframe (WEB_PREVIEW_HEIGHT = 560). Everything else the launcher can draw is on this page.
